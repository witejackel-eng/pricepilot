     1→     1→# BUILD A COMPLETE PRODUCT PRICING AND PROFIT OPTIMISER WEB APPLICATION
     2→     2→
     3→     3→Build a complete, working, production-quality web application called:
     4→     4→
     5→     5→# PricePilot
     6→     6→
     7→     7→PricePilot is a private product-pricing application for small businesses, wholesalers, retailers and ecommerce sellers.
     8→     8→
     9→     9→The user must be able to upload an Excel or CSV product sheet, configure business costs and profit goals, automatically calculate recommended selling prices for every product, review the results in an app-like dashboard, manually adjust recommendations and export the final data back to Excel.
    10→    10→
    11→    11→This must be a genuinely functional application.
    12→    12→
    13→    13→Do not create only a visual mockup, static dashboard, landing page or non-functional prototype.
    14→    14→
    15→    15→Every button, calculation, upload flow, filter, editable field, chart and export function must work.

    19→    19→# 1. PRIMARY USER PROBLEM
    20→    20→
    21→    21→The user currently manages products in Excel but does not want to manually create formulas.
    22→    22→
    23→    23→They want an application-like interface that:
    24→    24→
    25→    25→1. Accepts an existing Excel or CSV product sheet.
    26→    26→2. Detects relevant product columns.
    27→    27→3. Allows the user to map spreadsheet columns.
    28→    28→4. Adds business costs and pricing rules.
    29→    29→5. Calculates the actual total cost of every product.
    30→    30→6. Calculates break-even pricing.
    31→    31→7. Calculates markup, gross margin and estimated profit.
    32→    32→8. Recommends multiple selling-price options.
    33→    33→9. Identifies products that are underpriced or loss-making.
    34→    34→10. Allows prices to be adjusted manually.
    35→    35→11. Exports the completed product list to a new Excel file.
    36→    36→
    37→    37→The user should not need to understand or edit spreadsheet formulas.
    38→    38→
    39→    39→All calculations must happen automatically inside the application.

   412→   412→# 8. PRICING CALCULATION ENGINE
   413→   413→
   414→   414→Implement all calculations accurately using decimal-safe logic.
   415→   415→
   416→   416→Do not use normal floating-point arithmetic where it can cause financial rounding errors.
   417→   417→
   418→   418→Use a decimal arithmetic library if appropriate.
   419→   419→
   420→   420→All percentages and calculations must be protected against:
   421→   421→
   422→   422→* Division by zero
   423→   423→* Negative values
   424→   424→* Blank fields
   425→   425→* Invalid input
   426→   426→* Fees greater than 100%
   427→   427→* Tax rates greater than realistic values
   428→   428→* Margins at or above 100%
   429→   429→
   430→   430→## 8.1 Base cost
   431→   431→
   432→   432→Base cost should include:
   433→   433→
   434→   434→* Purchase cost
   435→   435→* Inbound shipping
   436→   436→* Packaging
   437→   437→* Handling
   438→   438→* Storage
   439→   439→* Advertising cost
   440→   440→* Other fixed cost
   441→   441→
   442→   442→## 8.2 Expected return cost
   443→   443→
   444→   444→Calculate expected return cost using:
   445→   445→
   446→   446→* Expected return rate
   447→   447→* Return handling cost
   448→   448→* Any unrecoverable product cost assumption

   451→   451→
   452→   452→* Fully recoverable

   454→   454→* Completely lost

   457→   457→
   458→   458→Calculate expected damage or wastage cost using:

   460→   460→* Product cost
   461→   461→* Damage percentage
   462→   462→
   463→   463→## 8.4 Total landed cost
   464→   464→
   465→   465→Total landed cost must include all fixed and expected costs attributable to one successful sale.
   466→   466→
   467→   467→## 8.5 Percentage selling fees
   468→   468→
   469→   469→Percentage-based selling fees can include:
   470→   470→
   471→   471→* Marketplace commission
   472→   472→* Payment gateway fee
   473→   473→* Other percentage cost
   474→   474→* Discount or coupon burden where relevant
   475→   475→
   476→   476→## 8.6 Break-even selling price
   477→   477→
   478→   478→Break-even selling price must account for:

   480→   480→* Total landed cost
   481→   481→* Percentage-based fees
   482→   482→* Fixed transaction fees
   483→   483→* Tax treatment
   484→   484→
   485→   485→The user must never be shown a break-even price that still produces a loss after fees.
   486→   486→
   487→   487→## 8.7 Markup
   488→   488→
   489→   489→Markup should be calculated internally as profit relative to cost.
   490→   490→
   491→   491→## 8.8 Margin

   493→   493→Margin should be calculated internally as profit relative to selling price.
   494→   494→
   495→   495→The interface should clearly distinguish markup from margin.
   496→   496→
   497→   497→Add an information tooltip:
   498→   498→
   499→   499→“Markup measures profit against cost. Margin measures profit against selling price.”
   500→   500→

   502→   502→
   503→   503→Generate four price recommendations.
   504→   504→
   505→   505→### Minimum Safe Price

   507→   507→The lowest price that satisfies:
   508→   508→
   509→   509→* Break-even requirements

   512→   512→* All fees and expected costs
   513→   513→

   517→   517→
   518→   518→Use competitor pricing when available.
   519→   519→
   520→   520→The competitive price should:
   521→   521→

   524→   524→* Flag the result when market prices are below the safe price
   525→   525→

   528→   528→The default recommendation.

   530→   530→It should balance:
   531→   531→
   532→   532→* Target profit margin
   533→   533→* Target markup
   534→   534→* Competitor average price
   535→   535→* Existing selling price
   536→   536→* Minimum profit
   537→   537→* Price rounding rules
   538→   538→

   544→   544→
