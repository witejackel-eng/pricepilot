# BUILD A COMPLETE PRODUCT PRICING AND PROFIT OPTIMISER WEB APPLICATION

Build a complete, working, production-quality web application called:

# PricePilot

PricePilot is a private product-pricing application for small businesses, wholesalers, retailers and ecommerce sellers.

The user must be able to upload an Excel or CSV product sheet, configure business costs and profit goals, automatically calculate recommended selling prices for every product, review the results in an app-like dashboard, manually adjust recommendations and export the final data back to Excel.

This must be a genuinely functional application.

Do not create only a visual mockup, static dashboard, landing page or non-functional prototype.

Every button, calculation, upload flow, filter, editable field, chart and export function must work.

---

# 1. PRIMARY USER PROBLEM

The user currently manages products in Excel but does not want to manually create formulas.

They want an application-like interface that:

1. Accepts an existing Excel or CSV product sheet.
2. Detects relevant product columns.
3. Allows the user to map spreadsheet columns.
4. Adds business costs and pricing rules.
5. Calculates the actual total cost of every product.
6. Calculates break-even pricing.
7. Calculates markup, gross margin and estimated profit.
8. Recommends multiple selling-price options.
9. Identifies products that are underpriced or loss-making.
10. Allows prices to be adjusted manually.
11. Exports the completed product list to a new Excel file.

The user should not need to understand or edit spreadsheet formulas.

All calculations must happen automatically inside the application.

# 8. PRICING CALCULATION ENGINE

Implement all calculations accurately using decimal-safe logic.

Do not use normal floating-point arithmetic where it can cause financial rounding errors.

Use a decimal arithmetic library if appropriate.

All percentages and calculations must be protected against:

* Division by zero
* Negative values
* Blank fields
* Invalid input
* Fees greater than 100%
* Tax rates greater than realistic values
* Margins at or above 100%

## 8.1 Base cost

Base cost should include:

* Purchase cost
* Inbound shipping
* Packaging
* Handling
* Storage
* Advertising cost
* Other fixed cost

## 8.2 Expected return cost

Calculate expected return cost using:

* Expected return rate
* Return handling cost
* Any unrecoverable product cost assumption

Allow the user to configure whether returned products are:

* Fully recoverable
* Partially recoverable
* Completely lost

## 8.3 Expected damage cost

Calculate expected damage or wastage cost using:

* Product cost
* Damage percentage

## 8.4 Total landed cost

Total landed cost must include all fixed and expected costs attributable to one successful sale.

## 8.5 Percentage selling fees

Percentage-based selling fees can include:

* Marketplace commission
* Payment gateway fee
* Other percentage cost
* Discount or coupon burden where relevant

## 8.6 Break-even selling price

Break-even selling price must account for:

* Total landed cost
* Percentage-based fees
* Fixed transaction fees
* Tax treatment

The user must never be shown a break-even price that still produces a loss after fees.

## 8.7 Markup

Markup should be calculated internally as profit relative to cost.

## 8.8 Margin

Margin should be calculated internally as profit relative to selling price.

The interface should clearly distinguish markup from margin.

Add an information tooltip:

“Markup measures profit against cost. Margin measures profit against selling price.”

## 8.9 Recommended price modes

Generate four price recommendations.

### Minimum Safe Price

The lowest price that satisfies:

* Break-even requirements
* Minimum margin
* Minimum profit per product
* All fees and expected costs

### Competitive Price

Prioritises market competitiveness.

Use competitor pricing when available.

The competitive price should:

* Remain above the minimum safe price
* Consider competitor lowest and average prices
* Flag the result when market prices are below the safe price

### Balanced Price

The default recommendation.

It should balance:

* Target profit margin
* Target markup
* Competitor average price
* Existing selling price
* Minimum profit
* Price rounding rules

### Premium Price

A higher-margin option.

It should consider:

* Premium target margin
* Competitor highest price
* Maximum acceptable market price
* Brand or category pricing rules

## 8.10 Recommended price selection

Default to the Balanced Price.

Allow the user to switch the selected recommendation to:

* Minimum
* Competitive
* Balanced
* Premium
* Custom

If the user selects Custom, allow manual price entry and instantly recalculate:

* Profit
* Markup
* Margin
* Fees
* Tax
* Price status
